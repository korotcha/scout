# Перенос данных и окружения

## Что копирование исходников переносит

Код, миграции, тесты, исторический свод, документацию, доступные референсы.
Git bundle содержит историю исходников, не содержимое облачной базы.

## Что остаётся в рабочем окружении

D1: analysis_projects, uploads, exclusions, subject_reviews, candidates,
screener_marks, calculator_settings, api_connections, query_analysis_jobs.

R2: оригиналы загруженных БД и отчётов, integration-checks,
search-demand/wb, query-analysis/wb, query-competitors/wb и прочие объекты,
на которые ссылаются записи uploads/исследований.

Токены MPStats/WB зашифрованы; ключ INTEGRATION_ENCRYPTION_KEY отдельно.
Доступ к Site, его секреты, реальные физические ID D1/R2 не выдаются экспортом исходников.
В `.openai/hosting.json` только логические bindings и идентификатор Site.

## Продолжение в том же Site

Переиспользовать текущий project_id и штатные инструменты Sites с доступом владельца.
Не менять секрет шифрования без миграции и не создавать новую пустую БД поверх старой.
Источники сначала push, затем сборка/публикация по текущему workflow среды.
Не использовать артефакт ZIP исходников как готовый deployment archive.

## Новый хостинг

1. Подготовить отдельное окружение и проверить Workers/Vinext-совместимость.
2. Создать новые DB/R2, применить миграции последовательно.
3. При наличии доступа администратора отдельно экспортировать рабочие таблицы
   и объекты. Согласовать точку снимка, чтобы записи/файлы не разошлись во времени.
4. Сохранить ID/foreign keys, object_key, ревизии и историю карточек. Проверить
   количество записей, суммы, связи и доступность файлов после импорта.
5. API-подключения безопаснее повторно настроить в новом окружении. Если переносить
   encrypted_key, нужен прежний ключ шифрования по защищённому каналу. Не хранить
   его в архиве или чате. Временные leases следует сбросить в новой копии.
6. Реализовать доверенную аутентификацию/роли. Произвольные внешние заголовки
   oai-authenticated-user-* принимать нельзя.
7. Проверить контрольные расчёты, загрузки, права, API и только затем переключать
   рабочий адрес. Исходный сайт оставить до подтверждения корректности переноса.

В текущем архиве **нет живого дампа**. Он не был доступен через разрешённые
инструменты экспорта в этой сессии. Это не означает, что данные утеряны.
