# MPStats: контракт, методика и границы подтверждения

## Обновление 25.09.2026: первый график — только по запросу

Для графика спроса/товаров нижеописанная старая схема заменена. Сначала читать
`docs/QUERY_DEMAND.md`, актуальный раздел в начале файла.

- Источник: `POST /api/seo/keywords/selection?date=YYYY-MM-01`, точный `word`.
  Проверен с API-ключом без cookies; это endpoint веб-отчёта «Подбор запросов»,
  а не метод из просмотренной публичной WB-спецификации.
- Поля: `wb_count` и `results`; не `count` (Ozon) и не `items` (первая страница).
- Месяц = отчёт на 1-е следующего месяца, окно частотности — предыдущие 30 дней.
  Не суммировать, не сдвигать даты и не добавлять fallback на соседний день.
- Не использовать артикул, категорию или Wildbox для заполнения этого ряда.
- «Кофемашина»: 36/36 парных месяцев. Сверены ВСЕ 18 строк исходного Excel
  конкурента (март 2025 — август 2026), совпали все три метрики без расхождений.
- Фикстура `tests/fixtures/query-demand-coffee-2026-09-25.json` отдельно хранит
  реальный снимок API и значения исходного Excel. Это только регрессионный
  эталон, никогда не источник данных приложения. Тест не заменяет live-сверку
  при изменении upstream-метода или его формата.
- Перед изменением метода: один ограниченный live-тест, проверка определения
  метрик и дат, затем полная сверка доступного эталона, после этого изменение
  кода. Не строить новую методику на гипотезе или совпадении одной точки.
- Остальные платные отчёты отключены. Старый кэш не удалён, новый источник
  сохраняется отдельно. Расход квоты в контрольном прогоне не вырос;
  бесплатность и неограниченная история для других запросов не гарантируются.

Дальнейшие разделы отражают прежнюю реализацию и дополнительные отчёты;
они не должны возвращать первый график к старому источнику или конвейеру.

База WB: `https://mpstats.io/api/analytics/v1/wb`.

внешней аналитики WB и SEO, не Ozon. Один тест частотности не уменьшил видимый
счётчик 10000; это наблюдение, не доказательство безлимитности всех методов.

## Что реализовано

| Метод | Назначение | Особенности |
|---|---|---|
| GET `/keywords/frequency?keyword=` | История date/frequency | Сохраняется весь ответ; глубина зависит от запроса и доступности |
| POST `/search/by_date` | items, brands, sellers, sales, revenue по месяцам | path, d1, d2, groupBy=month, fbs=1; запросы по годам |
| POST `/search/items` | Лидеры месяца и конкуренты сезона | path,d1,d2,fbs в URL; пагинация, sortModel/filterModel в JSON body |
| GET `/keywords/positions` | Текущая рекламная/органическая выдача | keyword,region_id=1; используем первую страницу, Москва |
| PUT `/groups?name=` | Создание группы | Только после выбора менеджером |
| PUT `/groups/{id}?skus=` | Добавление SKU | Повтор после сбоя использует сохранённый groupId |

Число шагов: частотность + агрегаты по годам + лидеры каждого месяца + текущая реклама.
Один клик ≠ один лимит отчёта. Списания зависят от тарифа. Графики/период по сохранённым
JSON работают без новых upstream-запросов. Конкуренты за отдельно выбранный сезон
требуют своего отчёта; их результат тоже сохраняется.

В R2: `search-demand/wb/{hash}.json`, `query-analysis/wb/{hash}.json`,
`query-competitors/wb/{hash(query|from|to)}.json`. Даты/источник и состояния шагов
сохраняются. В D1 query_analysis_jobs — lease для защиты от одновременных запросов.
При ошибке сохранённые шаги доступны; можно продолжить оставшиеся или повторить ошибки.
Это последовательность запросов из открытого браузера, не фоновая очередь Workers:
при закрытии окна выполнение останавливается после текущего шага.

## Частотность: что нельзя перепутать

Дата точки API не доказывает, что значение относится к одному этому дню.
В продукте показатель трактуется как замер за скользящий период; точное окно
и отличия источников ещё стоит письменно подтвердить в MPStats.
Нельзя суммировать пересекающиеся замеры или подписывать их как фактические
запросы за календарный месяц.

Эволюция: сначала сырые точки, затем среднее наблюдений месяца. Среднее давало
581148 за декабрь 2025 и не соответствовало референсу. Текущий алгоритм:
значение на 1-е следующего месяца; если такого нет — ближайшее предыдущее,
не старше 6 дней, с маркировкой ≈. Никакой интерполяции и подгонки к референсу.
Неполный текущий месяц не включается. Пропуск — null, не ноль.

На пользовательском ежедневном CSV «SEO - Проверка запросов. (21.09.2026).csv»
проверено для «кофемашина»:
- 01.11.2025 = 287653 → октябрь;
- 01.12.2025 = 408808 → ноябрь;
- 01.01.2026 = 429194 → декабрь.

Это совпадает с тремя месячными значениями скриншота конкурента. Это вывод из
сопоставления, а не подтверждённая разработчиком конкурента спецификация.
API с недельными точками может дать приблизительный результат: не обещать
429194, если точки 01.01 в его фактическом ответе нет. Значение 750461 внутри
периода не объявлять ни дневным объёмом, ни автоматически ошибкой данных.
Wildbox тоже расходится по значениям; его формула здесь не установлена.

## Прочие метрики

- Цена заказа = revenue/sales при ненулевых sales.
- revenue подписываем как объём заказов ₽, не подтверждённые оплаченные выкупы.
- Продажи карточек из выдачи не равны продажам, атрибутированным этому запросу.
- Топ-5/10 — среднее по фактическим доступным лидерам, если товаров меньше N,
  это меньшее число. Неполный ответ при большем total отвергается.
- Концентрация — сумма заказов лидеров / заказы всей сопоставимой выборки месяца.
  Если знаменатели расходятся и доля превышает 100%, не рисовать ложную долю.
- Одна карточка не равна одному продавцу и не доказывает монополию бренда.
- Частотность/товар — ориентир с разными временными основаниями, не конверсия.
- Пики сравниваются по одинаковым доступным месяцам соседних лет, минимум три;
  покрытие явно показывается. Максимум неполного года — не доказанный пик всего года.

## Что НЕ подтверждено / не подключено

- Новые методы анализа/групп проверены изолированными тестами на mock-ответах,
  но реальный доступ на тарифе и фактический формат пока не подтверждены.
- Историческая реклама по месяцам: positions даёт текущий снимок.
- Исторические новинки первой страницы: нужны состав выдачи, даты появления,
  определения нового бренда/продавца и история. Не заменять их просто числом новинок категории.
- Оплаченные выкупы и альтернативная расчётная выручка: нет подтверждённого
  сопоставимого временного ряда. Не умножать все заказы на произвольные 75%.
- Настоящий AI: не подключён. analysisVerdict — детерминированная сводка.
- Самый ранний доступный год не известен заранее. Запрос «максимум истории»
  не гарантирует наличие 3 лет, тем более истории с 2002 года.

Для обращения в поддержку подготовить метод, URL без токена, даты, безопасное
тело запроса, HTTP-код и очищенный фрагмент ответа. Ключи и заголовок с токеном
никогда не помещать в сообщения/скриншоты. Диагностика — /mpstats-check.
