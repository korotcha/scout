# Первый график запроса — 25 сентября 2026

## Актуально: прямой отчёт «Подбор запросов», без артикула

Этот раздел заменяет описанный ниже исторический SKU-метод и его fallback.
Подтверждён реальным вызовом с серверным API-ключом, без cookies браузера:

`POST https://mpstats.io/api/seo/keywords/selection?date=YYYY-MM-01`

```json
{"startRow":0,"endRow":2,"filterModel":{"word":{"filterType":"text","type":"equals","filter":"кофемашина"}},"sortModel":[]}
```

Заголовок авторизации — `X-Mpstats-TOKEN`; ключ остаётся на сервере.
Метод обнаружен в реально работающем интерфейсе MPStats и его публичном
клиентском модуле `assets-spa/oa-p_Nme.js`. В просмотренной публичной WB API
спецификации он не описан: это проверенный endpoint сайта, не обещание
стабильного публичного API-контракта. Ошибки и изменение формата останавливают
загрузку; платные аналитические методы не служат автоматической заменой.

- Проверяем ровно одну строку с точным нормализованным `word` и `total:1`.
- Частотность WB — `wb_count`, количество результатов всех страниц — `results`.
  `count` относится к Ozon, `items` — к выборке первой страницы. Они не подходят.
- Для августа 2026 используем отчёт **01.09.2026**, для декабря 2025 —
  **01.01.2026**. Частотность отчёта скользящая за предыдущие 30 дней, а не
  сумма за календарный месяц. Даты идут по календарю, не прыжками по 30 дней.
- Частотность на товар = `wb_count / results`, только при ненулевом знаменателе.
- По умолчанию 36 завершённых месяцев: 36 отчётов, а не один трёхлетний вызов.
  Сервер получает максимум шесть месяцев за POST; клиент продолжает до шести
  пакетов и останавливается при первой ошибке, без автоматического повтора.
- Каждый успешный месяц сохраняется в `.progress`. Возобновление загружает
  только недостающие месяцы. Явное обновление сохраняет прежний полный график
  до успешного завершения новой загрузки. Lease защищает одновременный пакет.
- Новый ключ: `query-demand/seo-wb/<sha256(query)>.json`. Старые SKU-объекты
  `query-demand/wb/...` и отдельная история частотности не удалены и не смешиваются.
- Пустой отчёт означает отсутствие строки запроса, а не ноль; замены соседним
  днём или интерполяции нет. `complete` означает получение всех отчётов,
  количество парных значений показано в UI отдельно.
- Поле артикула убрано. Перезагрузка, повторное открытие и фильтрация дат
  используют сохранённые данные без повторной загрузки MPStats.

## Источники и расчёт

- `/api/search-demand` использует прежнюю сохранённую историю частотности.
- `/api/query-demand` читает `query-demand/wb/<sha256(query)>.json` из object_store.
- При явной первоначальной загрузке количества результатов выполняются до трёх
  вызовов `POST /items/{referenceSku}/keywords` с точным фильтром `query`,
  годовыми интервалами от новых к старым. Частотность — ещё максимум один вызов.
  Успешные годы кэшируются отдельно по запросу, артикулу и границам периода.
- Считать нужно `data.words[точное совпадение query].dates[date].wb_count`
  и `total_found`. Агрегат `data.dates` не подходит.
- Артикул — технический источник наблюдений запроса, не фильтр по бренду.
  Автоматического платного поиска артикула нет; используется сохранённый
  источник или явно введённый в настройках.
- Месяцу соответствует замер на первое число следующего месяца. При пропуске
  берётся ближайшая предыдущая дата, не старше шести дней, с отметкой ≈.
  Обе величины берутся с одной даты. Отношение — их частное.
- При отсутствии парного замера товары и отношение пусты. Частотность при этом
  может быть показана из отдельной истории. Скользящие частотности не суммируются.
- Обычная кнопка переиспользует кэш независимо от пропусков. Обновление явное;
  автоматических повторов и дозагрузки пропусков нет. `resume` отдельно продолжает
  незавершённую загрузку с переиспользованием годовых частей; `refresh` обновляет
  все три года. Частичная история сохраняется с `complete:false` и предупреждением.
  Неудачное обновление не заменяет ранее сохранённую полную историю.
- Серверный `MPSTATS_API_KEY` позволяет работать без повторного ввода ключа
  в браузере. Он не возвращается клиенту; ключ из зашифрованного подключения
  остаётся запасным источником. Отключение серверного ключа — через окружение.
