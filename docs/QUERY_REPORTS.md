# Как оценивать отчёты по запросу

Актуально на 01.10.2026. По явному согласию пользователя подключены пять дополнительных
отчётов через `/api/query-items`. Загрузка только по отдельной кнопке; по умолчанию
два завершённых месяца. Первый график остаётся на `query-demand` (SEO).
Подсказки находятся в `lib/query-report-help.ts`, их компоненты — в
`app/query-report-help.tsx`. Подключение новых графиков должно переиспользовать
`ReportHelp`, а не копировать расходящиеся определения.

## Область анализа

`POST /search/items` принимает `path` — поисковую фразу. Она выбирает карточки,
но не атрибутирует все их заказы этой фразе. Анализируем выборку товаров по запросу
(условную поднишу), не весь предмет и не весь рынок. Товары могут получать заказы
по другим фразам, из рекомендаций и рекламы. Запросы могут пересекаться или
относиться к одному кластеру WB. Более длинная фраза не гарантирует меньше товаров
или иной состав. Нужна проверка релевантности моделей, аксессуаров и цены.

Объёмы перекрывающихся запросов нельзя складывать без дедупликации SKU. Сравнивать
периоды нужно с одинаковыми FBO/FBS, фильтрами и понятным составом. История выбранных
сегодня товаров не равна истории всей первой страницы: ушедшие товары могут отсутствовать.

## Что реально проверено

01.10.2026 два полных ответа `/search/items`, `path=кофемашина`, `fbs=0`,
календарные август и сентябрь 2026, `startRow=0,endRow=500`, revenue desc.
Размеры ответов 91/91 и 100/100. Свежий Excel конкурента от 01.10.2026:

- Заказы: 81 665 184 руб. / 6 304 шт. и 10 469 322 руб. / 777 шт. — совпали.
- Рекламные карточки: 50/91 и 100/100 — совпали при `search_ad_position_avg > 0`.
- Топ-1/5/10, средний чек, доли, расчётные показатели, бренды, supplier_id — совпали.
- Новые товары по sku_first_date — 9 и 9. Новые бренды/продавцы сентября как
  разность множеств — 3 и 7. Для августовских новых продавцов нужен июль.
- Оценка выкупов в штуках — совпала; в рублях расхождение +699 и +98 руб.
  Причина не установлена. Не подгонять ставки под Excel.
- В сентябре все 100 карточек имеют рекламный признак, но 38 одновременно имеют
  положительную органическую позицию. «100% рекламных карточек» не означает
  отсутствие органики или 100% рекламных мест.
- Исторические графики всех остальных месяцев не подтверждены этим тестом.
- В новом Excel текст ИИ не согласован с обновлёнными таблицами. ИИ не подключать.

Совпадение формулы не подтверждает область усреднения `search_ad_position_avg`:
в просмотренной публичной OpenAPI поле есть в примерах, но однозначного определения
«только данная фраза» не найдено. До подтверждения не называть его историей рекламного
аукциона именно этой фразы.

## Полезность для решения о входе

| Отчёт | Применение | Чего не доказывает | Чем дополнить |
|---|---|---|---|
| Спрос, товары, на товар | Сезонность интереса, сравнение одинаковых месяцев | Покупателей, конверсию, продажи на нового продавца | Заказы релевантных товаров, доля карточек с заказами |
| Рекламная активность | Косвенный сигнал распространённости продвижения | Рост ставок, стоимость заказа, отсутствие органики | Текущая рекламная выдача по фразе, наблюдения ставок; собственные сценарии CPC/CPA/ДРР |
| Новые товары/участники | Поиск запусков для изучения | Успех новичков, лёгкость входа, полную историю ушедших товаров | Заказы новичков и доля их заказов в выборке за сопоставимый возраст и сезон |
| Объём заказов, средний чек, лидеры | Масштаб выборки и ценовой ориентир | Прибыль, доходность новичка, доступный ему объём | Ценовые сегменты, медиана на активную карточку, собственная юнит-экономика |
| Заказы/оценка выкупов | Сезонность и сценарная оценка выкупа | Реальные выплаты, точный процент выкупа каждого SKU | Проверка обновлённых периодов, сценарии выкупа, отдельный расчёт возвратов и расходов |
| Концентрация и участники | Зависимость от лидеров | Монополию бизнеса по доле одного SKU, активность всех продавцов | Концентрация по supplier_id/брендам, продавцы с заказами |

Не использовать самостоятельный «балл входа» на основе числа новинок, отношения
частотность/товар, средней выручки топ-10 или доли рекламы. Это вспомогательные
показатели. Оценка входа требует релевантной модели, цены, поставки, расходов и бюджета.

## Проверенные в документации альтернативы (не новые live-тесты)

Официальная OpenAPI WB содержит:

- `POST /search/price_segmentation`: ценовая сегментация товаров по поисковой фразе,
  с path,d1,d2,fbs,minPrice,maxPrice,priceStep,segmentsCnt.
- `POST /search/sellers`: продавцы товаров по фразе, с периодом и FBS.
- `POST /search/brands`: бренды товаров по фразе, с периодом и FBS.
- `GET /keywords/positions`: рекламные и органические позиции именно по keyword
  на момент обращения; регион, до 5 страниц, лучшая позиция на уникальный товар.
  Это текущий снимок, не многолетняя история ставок.

Для экономии сначала используем уже загруженный ПОЛНЫЙ список карточек: из него
можно агрегировать доли по supplier_id, медиану, долю с заказами и группы цены.
Это наша группировка, не автоматически идентичная фирменному отчёту price_segmentation.
Отдельные платные методы нужны только при недостающих данных/полноте или для сверки.
Наличие метода в документации не подтверждает тариф, глубину истории или точную
стоимость. Не делать массовые 18/36 вызовов только ради UI-подсказок.

## Источники

- Официальная OpenAPI WB, проверена 01.10.2026:
  https://mpstats.io/integrations/redocusaurus/plugin-redoc-1.yaml
- Карточка товара: заказы, выкуп по предмету, кластеры запросов, поисковые позиции,
  FBO/FBS и их ограничения:
  https://wiki.mpstats.io/Wildberries/Поиск_по_SKU
- Рекламные кампании: отдельные показатели ставки, расходов, стоимости клика/заказа:
  https://wiki.mpstats.io/ru/Студия/Автобиддер/Автокампания

Исторический модуль «Сравнение WB+Ozon» помечен в вики как неработающий; не предлагать
его как действующий инструмент. Ценовая сегментация по поисковой фразе выше подтверждена
отдельно в действующей публичной API-схеме WB.

## Граница текущих UI-изменений

- В заголовке действующего графика — подробная подсказка и подпись о запросе.
- Под первым графиком — пять блоков, восемь диаграмм, сворачиваемые таблицы,
  общий выбор периода для дополнительных отчётов и подробные подсказки.
- Hover/focus — подсказка; нажатие/Enter — окно для чтения длинного текста;
  Escape и закрытие возвращают фокус. Подсказки не делают запросы к API.
- Старый `/api/query-analysis` всё ещё запрещает платные POST: старые вкладки не
  возобновят устаревший конвейер. Его кэш и первый график не изменены.

## Новый конвейер и тест 01.10.2026

- `query-items/fbo-v1/<query-hash>/<month>.json` в существующем object_store.
  Отдельный ключ на месяц. Хранятся поля исходных карточек, дата и полнота, не только суммы.
- Один POST — максимум одна страница по 500 карточек; общий лимит запуска UI 40 страниц.
  Максимум 10 000 карточек месяца: при превышении явная ошибка, не усечённая статистика.
- Полнота проверяется по total, смещению, числу строк и уникальности SKU.
  Неполный месяц не участвует в агрегатах; сохранённые страницы продолжаются после сбоя.
- Lease предотвращает одновременные запросы одного месяца. GET и открытие подсказок
  не обращаются к MPStats. Завершённые месяцы не обновляются автоматически.
- Фильтр 1–36 месяцев, только завершённые периоды. Новые бренды/продавцы = null,
  если предыдущий календарный месяц не сохранён полностью; его не догружаем скрыто.
- Непереданные числовые поля = null, не ноль. Реальный ноль сохраняется.
- Два live-вызова из UI: август 89/89 карточек, сентябрь 100/100.
  Суммы заказов 102 889 869 / 13 329 773 ₽; штуки 7 476 / 923.
  Это НЕ точное повторение утреннего Excel: состав выдачи успел измениться.
- Сверка SKU с утренними сырыми ответами: август +27/-29 карточек, 62 общих;
  сентябрь +32/-32, 68 общих. У ВСЕХ общих карточек sales/revenue не изменились.
  Разница сумм полностью объясняется добавленными/ушедшими карточками:
  август 24 410 454 - 3 185 769 = 21 224 685 ₽;
  сентябрь 3 338 072 - 477 621 = 2 860 451 ₽.
  Это наблюдение подтверждает чувствительность к составу выдачи на дату замера.
- Регрессионный тест использует компактные исходные строки утренних реальных ответов
  и независимые строки Excel в tests/fixtures/query-items-coffee-2026-10-01.json.
  Фикстура никогда не используется приложением или как подстановка в базу.
- Число вызовов UI — число HTTP-обращений, не подтверждённое списание тарифной квоты.
- Локально проверены: нажатие загрузки двух месяцев, восемь диаграмм, таблица,
  подробная подсказка, повторное открытие из БД, переключение 2/36 месяцев без
  загрузки новых отчётов. После исправления ключей React — нет error overlay и
  горизонтального переполнения. npm run build и 23 профильных теста прошли.
